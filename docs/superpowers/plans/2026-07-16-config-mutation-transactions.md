# 配置修改事务一致性实施计划

## 目标

把资源、自动化设置、改密和账号管理的九个主配置写函数迁移到统一的可重入事务边界，使用唯一临时文件原子替换，并在锁内按最新配置复核授权，消除跨领域并发覆盖和临时文件争用。

## 文件边界

- 新建 `backend/config_transactions.py`
- 修改 `backend/config.py`
- 修改 `backend/resources.py`
- 修改 `backend/settings.py`
- 修改 `backend/auth_api.py`
- 修改 `backend/accounts_admin.py`
- 修改 `app.py`
- 新建 `tests/test_config_transactions.py`
- 修改相关领域测试、`README.md` 和桌面中文总览

## 任务 1：共享事务层与原子文件替换

- [ ] 写共享锁失败测试，证明两个不同领域的写函数当前可以同时进入读取阶段。
- [ ] 新建 `backend/config_transactions.py`，实现 `config_mutation_transaction()` 和 `serialized_config_mutation()`。
- [ ] 修改 `save_config_raw()`：共享锁、唯一临时文件、flush、fsync、原子替换和异常清理。
- [ ] 测试保存成功、替换失败、清理失败容错和连续调用临时文件唯一性。
- [ ] 验证装饰器保留函数元数据并允许 `runtime` 注入。

## 任务 2：迁移九个配置写函数

- [ ] 删除资源模块私有事务锁和装饰器。
- [ ] 给资源新增、删除、确认增加共享事务装饰器。
- [ ] 给自动恢复、自动备份和证书续期开关增加共享事务装饰器。
- [ ] 给改密、账号新增/修改和账号删除增加共享事务装饰器。
- [ ] 保持配置保存、运行态更新和操作日志的原有响应语义。
- [ ] 运行资源、设置、账号聚焦回归。

## 任务 3：锁内最新配置鉴权

- [ ] 改密在锁内使用最新原始配置重新验证会话、当前密码和密码策略。
- [ ] 账号管理在锁内使用最新原始配置重新验证 admin 角色和自锁保护。
- [ ] 资源与设置路由在锁内重新加载配置并复核模式对应凭据。
- [ ] 同时携带错误模式凭据、等待期间会话撤销、账号禁用和角色降级均必须失败。
- [ ] 失败请求不得调用保存函数或写操作日志。

## 任务 4：确定性跨领域并发验证

- [ ] 资源新增与自动备份开关并发，最终两项修改都保留。
- [ ] 资源新增与账号新增并发，最终资源和账号都保留。
- [ ] 改密与证书续期开关并发，最终密码与证书配置都保留。
- [ ] 一个事务异常后，下一个事务可以正常执行。
- [ ] 测试使用 Barrier/Event，不使用依赖时间片的 sleep。

## 完成定义

- 九个配置写函数共享同一事务锁。
- `save_config_raw()` 不再使用固定临时文件。
- 跨领域并发测试可重复通过且不会丢更新。
- 权限变化后的旧请求不能写配置。
- 聚焦和全量测试全部通过。
- 中文文档准确且不暴露敏感配置或代码同步信息。
